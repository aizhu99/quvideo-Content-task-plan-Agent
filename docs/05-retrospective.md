# 05 复盘

## 最难的问题

最难的是让失败和约束结果真正影响下一步，而不是只留下日志。为此，Agent 每轮将工具观察和累计成功产物交回决策器，并将“已估算但不可行”与“估算工具本身失败”分开处理。预算不可行会继续尝试替代方案；工具故障会保留可复用的前序结果。

## 收获

- 结构化工具结果能让成本、工时和状态形成可复算的审查证据。
- 幂等要按业务请求识别，并校验同一 ID 是否对应相同内容。
- 离线 Mock 适合证明流程、边界与失败处理，不足以证明真实模型选择质量。

## 下一步

优先补充 API 鉴权/限流/超时及畸形响应的契约测试；随后扩大合成素材和真实模型成对评测样本，再考虑跨进程存储锁、失败步骤跨运行续跑和真实业务服务契约测试。请求内容冲突、存储写入失败及模型观察传递已有自动化测试。

## 投入时间与未完成项

实际用时：约 1.5 小时（按实现、API 接入、文档与最终验证的工作时段粗估；提交者可按实际投入修正）。代码已推送到 `https://github.com/aizhu99/quvideo-Content-task-plan-Agent`；最终 commit SHA 由仓库 `master` HEAD 确定并在提交信息中提供。未完成项：未接入真实素材、脚本生成、成本或保存业务系统；评审环境若无 API 凭据，只能运行离线 Mock。真实模型路径已用三条合成任务做有限实测，尚未进行大样本决策稳定性评测。
