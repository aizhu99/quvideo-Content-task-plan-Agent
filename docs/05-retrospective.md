# 05 复盘

## 最难的问题

最难的是让失败和约束结果真正影响下一步，而不是只留下日志。为此，Agent 每轮将工具观察和累计成功产物交回决策器，并将“已估算但不可行”与“估算工具本身失败”分开处理。预算不可行会继续尝试替代方案；工具故障会保留可复用的前序结果。

## 收获

- 结构化工具结果能让成本、工时和状态形成可复算的审查证据。
- 幂等要按业务请求识别，并校验同一 ID 是否对应相同内容。
- 离线 Mock 适合证明流程、边界与失败处理，不足以证明真实模型选择质量。

## 下一步

扩大合成素材和费用样本；为真实模型增加成对评测集并比较动作轨迹；把 JSON 存储替换为带事务和并发约束的数据层；加入失败步骤续跑入口及真实服务契约测试。

## 投入时间与未完成项

实际用时：约 1 小时（按本次实现、修正和本地验证工作会话估算）。未完成项：本地实现已验证离线 Mock，并在当前环境实际验证了 OpenAI 兼容模型路径；评审环境未必有相同模型服务。没有 GitHub 远程仓库，需由提交者发布并填写仓库 URL 与最终 commit SHA。
