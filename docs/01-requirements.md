# 01 需求

## 用户与目标

目标用户是内容运营人员。输入活动主题、预算与截止时间后，系统产出可审核的任务计划，避免超预算或错过截止时间。

## 范围

- 输入：`topic`、`budget`、带时区的 ISO 8601 `deadline`；可选 `start_at`、`request_id`。
- 材料：本地合成素材、授权费用、工具费用和耗时表，见 `data/campaign.json`。
- 工具：素材检索、脚本/任务步骤生成、成本与工时估算、方案草稿保存。
- 输出：计划任务及状态、工具结果、费用合计、保存结果或未完成原因，以及逐步 Trace。
- 保存仅写本地 JSON 草稿，不发布内容、不调用外部业务系统。

## 成功标准

1. 必填信息不足时指出缺失字段，不调用工具。
2. 费用包含素材授权与脚本生成两项；预估工时包含素材检索和生成耗时。
3. 模型观察到预算或截止时间不满足时，调整素材策略或生成模式，再次估算。
4. 仅当费用与工时均满足约束时保存；保存失败不能标记成功。
5. 工具失败后模型能依据失败结果调整或停止，先前成功结果仍保留。
6. 同一请求重复保存只保留一条方案；工具调用有明确上限。
7. Trace 记录动作、参数、返回摘要、后续动作和简要依据。
